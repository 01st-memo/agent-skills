# 動く資料（interactive-deck）

会議で「その内訳は？」と聞かれたとき、資料の中で答えが開くようにする。動きは飾りではなく、**見出しの判断を、見る人が自分の手で確かめるための操作**に限る。

## 位置づけ

- **中身は consulting-pptx-skill に従う。** 作る前に consulting-pptx-skill の `references/slide-rules.md` と `references/local-additions.md`（自作追記：逆テスト・線と塗りの意味・グラフの作法など）を全文読む（見出しは結論・1枚1メッセージ・左に図と右に意味合い・数字の出所・角丸禁止など）。このスキルは slide-rules.md と食い違うことを言わない。食い違って見えたら slide-rules.md が勝つ。
- **このスキルが足すのは3つだけ**：1ページ1操作（下の対応表）／根拠パネル／資料全体の動き（ズーム・一覧・自動デモ・止めても読める）。
- 使う場面：画面で開く・Artifact で送る・会議で画面共有する資料。**紙やPDFで配るなら使わない**（動きが無駄になる）。3〜5ページが目安。それ以上は章を分けるか consulting-pptx-skill で作る。

## 構造 → 操作の対応表（1ページに1つだけ）

見出しを書いたら「この文は何の形の主張か」を1語で言い、表から操作を引く。センスで選ばない。見出しと関係ない動きは入れない。図の名前（棒グラフ・ウォーターフォール・KPIツリーなど40個）から引くなら、consulting-pptx-skill の `references/chart-name-index.md` の「動かすなら」列にこの6つのどれを付けるかが書いてある。

| 見出しの構造 | 見出しの例 | 付ける操作 | 見本 |
| --- | --- | --- | --- |
| 結論と根拠 | 〜の鍵は〜にある | 押すと下の階層（内訳）が開く | p.1 の数字の帯・p.2 の棒 |
| 切り口 | 〜を食うのは〜ではなく〜だ | 切り口（指標・立場・年）を切り替えると全部の棒が並び替わる | p.2 時間／件数 |
| 差分 | 〜で減るのは〜に限られる | 前が後へ形を変え、消えた分が**同じ位置に**破線で残る | p.3 |
| 因果 | 〜を広げれば〜が浮く | 条件をスライダーで動かすと結果が再計算され、式が画面に出る | p.4 |
| 不足と打ち手 | 〜だけでは届かず〜が要る | 打ち手をオン・オフすると不足が埋まる・残る。打ち手から根拠ページへ飛べる | p.5 |
| 順序 | 〜の順に進めれば〜 | 順に組み上がる／主体が工程を進む／時間軸に「いま」の線 | p.1 の流れ |

- 量を表す動き（棒の長さ・不足の幅）は必ず値から計算する。手で長さを置かない。
- 相関しか無い数字に「因果」の操作を付けない（スライダーは因果の言い切りに見える）。付けるなら「試算」と書き、式と前提を画面に出す。

## 根拠パネル（ほぼ全ページ）

押すと右から出る幅720pxのパネル。後ろを暗くし、×・Esc・後ろを押すと閉じる。上から順に：どこの話か（「現状 › 過去提案書」）→ 言えることを1〜2行 → タブ2つまで（例：内訳／出所と前提）→ 小さな表 → 出所。**本体に載せきれない数字の置き場**であり、本体の数字と矛盾させない。

## 1ページの型

- 2ページ目以降：左に主役の図（幅1,060px）、右に淡い地のパネル（大きな数字1つ → それが何か1行 → 補足2〜3行 → 比べる相手と差を**計算式つきで** → 「内訳を見る ›」）。slide-rules の「左＝事実・図、右＝意味合い」と同じ。
- 1ページ目：上に数字の帯（3つまで）、下に流れか構造。流れの各所に、そのページへズームで入る入口（「p.2 ›」）を置く。
- 色：主役は主役色、比べる相手は薄い段階色、それ以外は灰。強調色（--hi）は資料全体で1か所。大きな数字は1ページに1つ（p.1 の帯は例外）。
- 押せるものは見て分かるようにする：「›」「押すと〜」の文言、ホバーで枠、ページに入って3秒後に1回だけ輪で知らせる（`.hint`）。棒や点はホバーで「値・名前・出所」の吹き出し（`data-tip="値|名前|出所"`）。
- 見出しは**1行36字以内**（画面で縮むため2行にしない）。「A。B」の二段構えにしない。文末を隣のページとそろえない。
- 文字は最小18px。本体の下に空白の帯を残さない。

## 資料全体の動き（見本の土台に入っている）

- **常設ナビ**：出所行の右端に「全体像／‹ 前へ／p.3 / 5／次へ ›」を常に出す（ページの外に1つだけ置くので、ズームで入った後も一覧中も効く）。「全体像」は入ってきた入口カードへ引き戻すズームアウトで p.1 に戻る。マウスだけの人が迷子にならないための土台なので消さない。出所の文は左寄せで、右端をナビに空けておく。
- キー：→・Space 次／← 前／数字 移動／Esc 閉じる・一覧を出る・全体像へ戻る／O 全ページ一覧（見出しを縦に読む画面）／D 自動デモ。スマホは左右スワイプ。
- ページに入ると約3秒で組み上がる：見出し → 図（棒は0から伸び60msずつずらす）→ 数字 → 右パネル。`.rv` と `.grow` に `--d:遅延` を付けるだけ。
- **止めても読める**：URL に `#static` を付けるか OS の「視差効果を減らす」設定なら、組み上がった最終状態を出す。操作で変わるページは**見出しの判断が見える状態**にする（例：打ち手はすべてオン、差分は「後」）。これを各ページの `P.<id>.final` に書く。
- `#p3` で3ページ目から開く。`#check` で自己点検。

## 手順

1. **slide-rules.md と local-additions.md を全文読む。** 目的・読み手・決めてほしいことが素材から読めないときだけ、作る前にまとめて1回聞く。
2. **数字台帳**を作る（項目・値・時点・出所・母集団）。素材に無い数字は置かない（「xx」で残して注記）。差や比は計算して式を残す。
3. **見出しを全ページ先に書き**、縦に読んで「全体像 → 根拠 → 打ち手」の筋が通るか確かめる。
4. **ページ一覧表**を作る：| p | 見出し | 構造 | 操作 | 根拠パネルの中身 | static の状態 |。操作は対応表から引く。
5. `templates/deck.html` を作業場所へコピーし、書き換える。**土台（「土台（触らない）」の区画）には手を入れない。** 差し替えるのは：
   - `<section class="pg" data-id="…">` の中身（1ページ＝1 section）
   - データ定数（先頭の「データ」区画）
   - `P.<id> = { init, final }`（入ったときの状態／止めたときの状態）
   - `DRAWERS.<名前> = el => ({ crumb, claim, tabs, src })`（`data-drawer="<名前>"` を付けた要素を押すと開く）
   - `DEMO` 台本（`{ t: 'data-demo の名前', do: 'click' | 'slide', to }`・`{ go: ページ番号-1 }`・`{ key: 'Escape' | 'o' }`・最後は `{ key: 'o' }` で一覧に終える）
   - 押す要素には `data-op`（見出しを確かめる操作）を、自動デモで触る要素には `data-demo` を付ける。ページ間の移動は `data-op="zoom" data-go="<ページ番号-1>"`。
6. **点検**：`node <このスキルの場所>/scripts/check.mjs <deck.html> [出力フォルダ]` → **FAIL 0**。自己点検（操作と根拠パネルの有無・36字・18px・はみ出し・重なり・短いラベルの折り返し・空白帯・文末の連続・デモ台本の参照先）と、実操作（各ページの操作・根拠パネルの開閉・ズーム・一覧・自動デモ完走・JSエラー）を見る。playwright は consulting-pptx-skill に入れたものを使う（無ければ consulting-pptx-skill のフォルダで `npm run setup`。別の場所にあるなら `PLAYWRIGHT_MODULE_DIR` で node_modules を指す）。playwright が無い環境では、Chrome で自己点検だけ回せる：`chrome --headless=new --window-size=1920,1080 --virtual-time-budget=3000 --dump-dom "file:///…/deck.html#check"` の出力末尾の `<pre id="selfcheck">` が OK なら通過。
7. **出力フォルダの p1〜pN.png と overview.png を全部目で見る。** 機械は「判断が図から見えるか」「棒が潰れていないか」を見ない。
8. **出す**：Artifact で出すか、HTMLファイルで渡す。大きさは45KB前後が目安（見本が約43KB）。膨らんだら文章を削る（図・根拠パネル・操作は削らない）。返答の本文（HTMLの外）に短く書く：ページ一覧表・数字台帳・操作方法（キー一覧）。最後に、さらに良くする方向を2〜3個挙げて選んでもらう。

## 見た目の既定

consulting-pptx-skill の cool スキンと同じトークン（`:root`）。warm スキンにするときは `:root` だけ差し替える。書体はシステムフォント（見出し明朝・本文ゴシック）で外部読み込みなし。1920×1080 のキャンバスを画面に合わせて縮める。

## 出典

「見出しの構造から操作を1つに決める」「根拠パネル」「止めても読める」の考え方は、うちた氏の note「AIスライドを『クリックで深掘りできる資料』にしてみた」（2026-09-26）による。プロンプトと見本コードは写しておらず、このスキルの文章・見本・土台・点検はすべて書き直したもの。
